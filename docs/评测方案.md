# 评测方案

## 目标

将“模型文件正确”“离线动作误差下降”和“闭环任务成功”分开验证，避免用训练 loss 代替
比赛指标。

## 第一阶段：模型与接口检查

- 校验模型包 SHA-256；
- 检查 `config.json`、tokenizer、权重和 `norm_stats.pkl`；
- 检查动作 chunk 为 25、视频编码开启；
- 在策略 GPU 上完成模型加载；
- 使用 XPolicyLab debug client 检查观测、动作 key 和维度。

## 第二阶段：本机闭环冒烟

GOAI 2026 初赛只评测 Generalization。先对全部 24 个可运行配置各执行 1 个 episode：

```text
12 个标准任务
12 个对应的 _random 配置
```

冒烟只用于验证端到端链路，不用于比较榜单成绩。当前 step-199999 已完成该阶段，结果见
`docs/冒烟测试报告.md`。

## 第三阶段：官方初赛评测

按测评群当前口径，官方评测为 24 个配置、每配置 `eval_num=25`、3 个 seed，合计 1,800
个 episode，并对 seed 结果取平均；最终仍以主办方正式通知和结果邮件为准。至少记录：

| 字段 | 说明 |
|---|---|
| task | 任务名 |
| checkpoint | checkpoint step |
| seed | 环境 seed |
| episodes | 有效 episode 数 |
| successes | 成功次数 |
| failures | 失败次数 |
| success_rate | 成功率 |
| mean_steps | 平均执行步数 |
| mean_time_s | 平均完成时间 |
| simulator | Isaac Sim/RoboDojo 版本 |
| notes | 失败类型与异常说明 |

结果写入 `results/metrics/evaluation_results.csv`。未完成测试前不填写推测值。

线上仿真赛段并非只按二元成功率判定。根据参赛手册，系统还会综合任务完成质量、执行
效果与系统表现，各任务得分的平均值原则上构成最终表现得分。

## checkpoint 选择

每 10,000 step 保存一次 checkpoint。结合离线指标、队友机器正确性验证和部署前检查，
正式申请前固定选择 step-199999。评测申请后不再更换模型、norm stats 或 `action_type`。
