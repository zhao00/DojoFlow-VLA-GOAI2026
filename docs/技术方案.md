# DojoFlow-VLA 技术方案

## 1. 赛题理解

GOAI 赛题一要求基于 X-Eval 仿真与真机一体化评测平台，面向 12 个仿真任务和 6 个真机
任务优化端到端具身操作模型，并从任务成功率、泛化能力、执行效率和鲁棒性等维度验证。
本项目选择“VLA 通用操作模型 + 双臂协同 + 仿真辅助迭代”路线。

当前阶段以官方仿真数据完成监督微调，并通过 XPolicyLab 的标准策略接口完成 24 个
Generalization 配置的本地闭环冒烟评测；真机测试作为后续阶段目标。正式初赛成绩仍以
主办方邮件为准。

## 2. 系统架构

```text
任务语言指令
      +
头部 RGB / 左腕 RGB / 右腕 RGB（6帧历史）
      +
双臂末端位姿与夹爪状态
      │
      ▼
Hy-Embodied-0.5-VLA
  ├─ 视觉语言主干
  ├─ 时空视觉记忆编码
  └─ 双塔 Flow-Matching 动作专家
      │
      ▼
25步相对 EE RT 动作序列
      │
UMI坐标逆变换 + 反归一化 + 动作分块执行
      │
      ▼
XPolicyLab Policy Server ──WebSocket── RoboDojo/X-Eval Client
```

模型推理与仿真环境进程分离：大模型可部署在 H200 等计算服务器，Isaac Sim 客户端部署在
具备仿真环境的机器上。二者通过 XPolicyLab WebSocket 协议交换标准化观测和动作。

## 3. 模型与流匹配动作专家

### 3.1 基础模型

项目从公开的 `Hy-Embodied-0.5-VLA-UMI` 初始化完整 VLA 权重，使用上游公开训练代码完成
全参数微调。最终训练日志统计约 4.527B 个可训练参数。

### 3.2 条件流匹配

设真实动作序列为 $a$，高斯噪声为 $\epsilon$，时间 $t$ 从 Beta 分布采样。训练构造：

$$
x_t = t\epsilon + (1-t)a, \qquad u_t = \epsilon-a
$$

动作专家在图像、语言和机器人状态条件下预测速度场 $v_\theta(x_t,t\mid c)$，优化：

$$
\mathcal{L}_{flow}=\lVert v_\theta-u_t\rVert_2^2
$$

推理从高斯噪声开始，使用上游配置的 10 个 Euler 步反向积分速度场，得到连续动作序列。
这正是项目名称中 `Flow` 的技术来源。

### 3.3 动作表征

- `action_chunk_size=25`；
- `act_type=relative_chunk_ee_RT`；
- 双臂各 10 维训练表征，总计 20 维；
- 输入状态统计为 20 维；
- 使用 RoboDojo 到 UMI 坐标变换；
- 推理部署采用 EE 动作接口，而不是 joint 动作接口。

## 4. 数据方案

数据来自 GOAI/RoboDojo 官方 HDF5 数据集：12 个任务，每任务 100 条轨迹，共 1,200 条
轨迹和 592,432 个时间步。每个时间步展开为一个训练样本，包含三视角图像、语言指令、
机器人状态以及未来 25 步动作，因此训练样本数大于轨迹数。

关键数据配置：

| 项目 | 配置 |
|---|---|
| 相机 | 头部、左腕、右腕，共 3 路 RGB |
| 图像尺寸 | 224×224 |
| 历史长度 | 6 帧 |
| action chunk | 25 |
| downsample | 1 |
| 坐标 | UMI frame |
| 图像增强 | 开启随机裁剪与亮度调整 |
| 样本枚举 | deterministic |

归一化统计由上游 `compute_norm_robodojo.py` 生成。训练、69999 导出模型和最终 199999
导出模型使用同一份文件，其 SHA-256 为：

```text
8ab506debab53fd20b0235a0e025f10daf3973d5a9ab8111e0f67a27a331e319
```

## 5. 训练方案

| 配置 | 实际值 |
|---|---|
| 计算资源 | 单机 4×NVIDIA H200 |
| 精度 | BF16 |
| 分布式 | Accelerate + DeepSpeed ZeRO-2 |
| 微调方式 | 全参数监督微调 |
| 每卡 batch | 8 |
| 全局 batch | 32 |
| 梯度累积 | 1 |
| 最大步数 | 200,000 |
| 数据 epoch | 约 10.8 |
| 峰值学习率 | 5e-5 |
| warmup | 1,000 |
| cosine decay | 150,000 |
| 学习率底值 | 5e-6 |
| checkpoint | 每 10,000 step |
| validation | 每 5,000 step、100 个 batch |
| seed | 42 |

训练服务器不访问公网。依赖环境、上游源码和基础权重先在联网机器准备，再通过可校验归档
传入服务器。该过程不改变训练算法，但保证了隔离环境中的可复现性。

## 6. 部署方案

项目不复制或重写 XPolicyLab 已提供的 Hy-VLA 部署适配器，而是固定其版本并提供配置、
路径约定和验证说明。部署关键项：

- policy：`Hy_Embodied_05_VLA`；
- benchmark：`RoboDojo`；
- embodiment：`arx_x5`；
- action type：`ee`；
- checkpoint：导出的自包含目录；
- norm path：与训练一致的 `norm_stats.pkl`；
- UMI coordinate frame：开启；
- history：6 帧；
- policy server 与 environment client：WebSocket 分机部署。

## 7. 验证方案

验证分四层：

1. **文件完整性**：模型 tar 和 norm stats SHA-256；
2. **模型有效性**：配置、tokenizer、权重、参数有限性、GPU 加载；
3. **离线代理指标**：train loss、val loss、动作 L1 距离、分 chunk/维度误差；
4. **闭环评测**：固定任务、seed 和 episode 数，记录成功率、执行时长和失败类型。

训练代码的 validation 使用训练 dataloader，因此第 3 层只能用于训练监控和候选 checkpoint
筛选，不能作为比赛闭环成绩。最终结果以第 4 层为准。

## 8. 开源贡献与边界

本项目开放的是可复现工程流程、配置、验证和部署说明。Hy-VLA、XPolicyLab、RoboDojo、
官方数据和 Isaac Sim 分别属于其原作者；仓库通过固定版本、第三方清单和调用接口明确边界，
不将上游模型架构或适配器宣称为自研。

本仓库不会公开服务器凭证、私有路径、官方数据副本和未经授权的模型下载地址。

## 9. 闭环结果与正式评测状态

独立部署机使用 step-199999、`action_type=ee`，完成 12 个标准配置和 12 个 `_random`
配置的闭环冒烟。24/24 配置成功生成结果文件；按每配置已经观察到的有效 seed 成功覆盖
统计，`fold_clothes`、`stack_bowls` 与 `pour_liquid_into_cup` 二元成功，总体为
3/24（12.50%）。其中前两项来自 seed 0，第三项来自补充 seed 1；原始 seed 0 的 24 项
`score` 简单平均仍为 11.67。逐配置结果见 `docs/冒烟测试报告.md`。

该测试只用于端到端自测。公网 WSS 正式评测试运行期间出现大观测帧导致的 keepalive
超时和反复重连，未观察到模型 OOM 或推理 traceback。经主办方同意，代码和 checkpoint
已通过私有 ModelScope 仓库交付。主办方仍在执行正式评测，预计无法在本次复杂材料截止前
回传，因此当前提交材料中的正式成绩字段均为占位内容，待结果邮件返回后替换。
