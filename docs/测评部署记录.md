## 4. 本地冒烟命令

在 RoboDojo 仓库根目录设置实际环境后运行：

```bash
POLICY_DIR="XPolicyLab/policy/Hy_Embodied_05_VLA"
POLICY_ENV="uv"
RUN_LABEL="HyVLA-GOAI-step-199999"
ACTION_TYPE="ee"

bash scripts/robodojo.sh smoke \
  --dimension generalization \
  --policy-dir "${POLICY_DIR}" \
  --ckpt "${RUN_LABEL}" \
  --policy-env "${POLICY_ENV}" \
  --eval-env RoboDojo \
  --action-type "${ACTION_TYPE}" \
  --eval-num 1 \
  --seed 0
```

本机为避免模型或依赖意外联网，评测启动脚本还设置了 Hugging Face/Transformers/Datasets
离线变量并清除了 HTTP(S)/ALL_PROXY。模型、数据和仿真资产均从本地读取。

## 5. 公网 Policy Server 试运行

策略服务器曾通过 GPU 云平台提供的 TLS 反向代理暴露为 WSS 端点。外部客户端可以完成
TCP 与 WebSocket 握手，服务器也能稳定加载模型；但主办方正式评测持续出现
`keepalive ping timeout` 和重连。

排查结果显示，正常批量观测会通过 msgpack 直接传输三路 640×480 RGB 数组：单环境约
2.76 MB，10 环境约 27.65 MB。大帧经公网 WSS 代理传输并叠加推理时间后，容易超过默认
20 秒 keepalive 窗口。服务器日志未出现 CUDA OOM 或模型 traceback，因此该问题归类为
远程传输/keepalive 稳定性问题，而非 checkpoint 加载失败。

建议的协议层修复为：客户端发送前对相机观测做 JPEG 编码，并将客户端和服务器的
keepalive interval/timeout 提高到至少 120 秒。主办方本地评测可以直接避开公网传输瓶颈。
